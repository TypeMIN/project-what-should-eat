# Phase 0 — 카카오맵 음식점 카테고리 분석

## 목적

`category_group_code=FD6`(음식점)으로 조회되는 `category_name`이 서비스 내부 음식 분류(대분류/중분류) 체계를 지탱할 만큼 세분화되고 일관적인지 실제 데이터로 확인한다. `PRODUCT.md`의 Unknown("외부 지도 서비스가 주는 식당 카테고리 정보가 내부 음식 분류를 지탱할 만큼 세분화되고 일관적인지")에 대한 1차 답을 만드는 것이 목표다.

## 방법

서로 다른 4개 상권 유형에서 2개씩, 총 8개 좌표를 중심으로 반경 1km 내 `FD6` 카테고리 검색을 페이지 상한까지 수집했다.

| 상권 유형 | 중심점 |
|---|---|
| 오피스 상권 | 마곡나루역, 마곡역 |
| 대학가 | 신촌역, 이대역 |
| 주거지역 | 방배역, 이수역 |
| 번화가 | 홍대입구역, 상수역 |

**한계 1 — 반경 내 전체가 아니라 45곳 샘플이다.** 8개 중심점 모두 `meta.pageable_count`가 45로 고정되어 있었고, 실제 `total_count`는 340~2,538건으로 훨씬 많았다(카카오 API 자체의 페이지 상한: `size` 최대 15 × `page` 최대 3). 즉 이 분석은 "반경 1km 내 음식점 전수조사"가 아니다. 지역별 음식점 밀도나 절대 개수 비교에는 쓸 수 없다.

**한계 2 — 이 45곳은 "가장 가까운 45곳"이 아니다.** 수집 스크립트가 `sort` 파라미터를 지정하지 않아 카카오 기본 정렬(정확도순)로 가져왔다. 후속 검증에서 확인한 바로는 `sort=distance`를 지정하면 **완전히 다른 45곳**이 반환된다(홍대입구 기준 정확도순 45곳의 거리 범위는 85~710m, 거리순 45곳은 9~129m). 따라서 이 표본은 "정확도순 상위 45곳"이며, 실제 서비스가 거리순으로 조회할 경우의 후보 풀과 동일하지 않다.

이 차이는 실제로 분포에 영향을 준다. 아래 분석의 술집·간식 비중은 정확도순 표본에서 35/360 ≈ 9.7%였지만, 같은 4개 지역을 거리순으로 다시 조회하면 33/180 ≈ 18.3%로 약 2배였다. 가까운 곳일수록 술집·카페 비중이 높다.

**따라서 아래의 빈도·비율 수치(레벨3 존재 비율 76.4% 포함)는 정확도순 표본 기준이며, 거리순 후보 풀에서는 다를 수 있다.** 다만 이 조사의 목적이었던 카테고리 *어휘와 구조* 파악(레벨2 값의 종류, 계층 깊이, 쉼표 묶음, 상호명 혼입)에는 영향이 없고, 이를 근거로 한 `docs/decisions/food-category-taxonomy.md`의 결정도 유지된다 — 술집·간식 제외는 18%에서 오히려 더 정당해지고, `아시아음식 > 동남아음식` 계층은 표본과 무관한 구조적 사실이다.

총 수집 행: **360건** (8 × 45), distinct `category_name`: **70종**.

## 결과

### 1. 깊이(계층) 분포

`category_name`을 `>`로 분리했을 때의 토큰 수(레벨1 "음식점" 포함):

| 깊이 | 건수 | 비율 |
|---|---|---|
| 2 (음식점 > 대분류) | 85 | 23.6% |
| 3 (… > 중분류) | 215 | 59.7% |
| 4 (… > 소분류) | 56 | 15.6% |
| 5 | 4 | 1.1% |

깊이 3이 압도적 다수다. 즉 카카오 카테고리는 "대분류만 있고 끝"인 경우가 24%, "대분류 + 중분류"까지 있는 경우가 60%에 달한다.

### 2. 레벨3(중분류) 존재 비율

**275 / 360 = 76.4%**가 레벨3(중분류에 해당하는 값)을 갖고 있다. 브리프에서 가장 핵심적으로 열려 있던 질문 — "중분류(국밥, 고기, 돈까스, 초밥, 라멘 등)를 설계할 수 있는가" — 에 대해 **"대부분 가능하다"**는 답이 나온다. 다만 나머지 24%(깊이 2)는 중분류 없이 대분류로만 남으므로, 중분류가 없는 경우를 위한 fallback(대분류 단위 매칭)이 필요하다.

### 4. 지역 간 어휘 일관성

4개 상권 유형에 공통으로 나타나는 값(한식·일식·중식·양식·간식·술집·아시아음식·분식)은 전 지역에서 동일했다. 지역별로만 나타난 값은 표본 크기가 작아 생긴 우연에 가깝다:

- 오피스(마곡)에만: 패밀리레스토랑, 뷔페
- 대학가(신촌·이대)에만: 도시락
- 주거지역(방배·이수)에만: 패스트푸드
- 번화가(홍대·상수)에만: 없음

**핵심 대분류 어휘(한식/일식/중식/양식/간식/술집/아시아음식/분식)는 상권 유형에 관계없이 안정적**이라고 볼 수 있다. 나머지 소수 값은 지역 특성이라기보다 표본 변동으로 보인다.

### 5. 예외 사례

- **쉼표로 묶인 최하위 레벨** — 111/360(30.8%)건이 `한식 > 육류,고기`, `일식 > 초밥,롤`, `한식 > 찌개,전골`처럼 최하위 레벨이 단일 값이 아니라 쉼표로 묶인 복수 값이다. 내부 중분류로 옮길 때 1:1이 아니라 1:N 매핑(하나의 카카오 leaf → 여러 내부 태그)이 필요하다.
- **브리프의 "동남아"는 카카오의 대분류가 아니라 중분류다** — `아시아음식 > 동남아음식 > 베트남음식`처럼, 카카오는 "아시아음식"을 대분류로 두고 그 아래에 "동남아음식"이 중분류로 들어간다. 브리프가 가정한 "한식/일식/중식/양식/동남아"를 같은 층위의 대분류로 두려면, 카카오의 대분류 "아시아음식"을 그대로 쓰지 않고 내부적으로 재구성(중분류를 대분류로 승격)하는 결정이 필요하다.
- **레벨5는 카테고리가 아니라 상호명이 섞여 나온다** — `한식 > 국수 > 칼국수 > 달인대보칼국수`, `아시아음식 > 동남아음식 > 베트남음식 > 에머이`처럼 4건 모두 마지막 토큰이 실제 프랜차이즈/상호명이었다. 깊이 5는 분류 체계로 신뢰할 수 없고, 매핑은 레벨 4까지만 다루는 것이 안전하다.
- **FD6에는 "식사"로 보기 애매한 항목이 섞여 있다** — 술집(16건, 호프·요리주점·일본식주점·실내포장마차), 간식(19건, 대부분 제과·베이커리)은 카카오 기준으로는 음식점(FD6)이지만 "오늘 뭐 먹지"가 뜻하는 한 끼 식사 후보로 볼지는 별개의 판단이다. 이번 조사는 존재를 확인했을 뿐, 포함/제외는 결정하지 않았다.

## 후속 검증 — 못 먹는 음식 필터가 가능한가

`category_name`과 상호명만으로 "못 먹는 음식"을 걸러낼 수 있는지 별도로 확인했다. 홍대입구역 기준 거리순 45곳에 실제 사용자가 입력할 법한 단어를 넣어본 결과다.

| 입력 단어 | 매칭된 곳 |
|---|---|
| 새우 | 0 |
| 땅콩 | 0 |
| 우유 | 0 |
| 계란 | 0 |
| 오징어 | 0 |
| 견과류 | 0 |
| 매운 | 0 |
| 고기 | 6 |
| 해물 | 1 |
| 생선 | 1 |

카카오 장소 데이터에는 재료 정보가 전혀 없다. 매칭되는 것은 "고기", "해물", "생선"처럼 카테고리 대분류 수준의 단어뿐이고, **실제 알레르겐은 하나도 걸러지지 않는다.** "매운 음식"은 대응하는 카테고리 자체가 없어 어떤 방식으로도 걸러낼 수 없다.

따라서 카카오 데이터만으로 가능한 최대치는 "음식 종류 단위 제외"(해산물, 돼지고기 등을 카테고리로 걸러내기)이며, 재료 단위 제외는 불가능하다. 자유 텍스트 입력창을 두면 사용자에게 걸러진다는 잘못된 안전감을 주게 된다.

참고로 카테고리 필터만 적용했을 때의 후보 생존 수는 충분하다. 거리순 45곳에서 술집·간식을 제외하면 마곡나루 32곳, 신촌 41곳, 방배 36곳, 홍대입구 38곳이 남는다.

## 대분류/중분류 매핑 제안 (초안 — 확정 아님)

데이터 기반으로 제안하되, 최종 확정은 아니다.

| 내부 대분류 | 카카오 레벨2 소스 | 비고 |
|---|---|---|
| 한식 | 한식 | 그대로 |
| 중식 | 중식 | 그대로 |
| 일식 | 일식 | 그대로 |
| 양식 | 양식, 패밀리레스토랑, 패스트푸드 | 후 2개는 건수가 적어 양식에 통합 |
| 아시아음식(동남아 포함) | 아시아음식 | 중분류(동남아음식/인도음식 등)로 세분화 |
| 분식 | 분식 | 그대로 |
| 치킨 | 치킨 | 별도 유지(한국 배달/식사 문화상 독립 카테고리로 흔함) |
| (스코프 판단 필요) | 술집, 간식, 샤브샤브, 뷔페, 도시락, 퓨전요리 | 건수 적음 + "한 끼 식사" 여부가 애매 → 포함/제외를 별도로 결정해야 함 |

중분류는 레벨3 값을 그대로 쓰되, 쉼표로 묶인 값은 분리해 여러 내부 태그로 매핑하고, 레벨3이 없는 24%는 대분류 단위로만 매칭한다.
