# 04 — A/B 선택과 결과 저장

## Outcome

후보를 받은 세션 진행자가 두 식당 카드 중 하나씩 고르는 과정을 반복해 최종 식당 하나에 도달하고, 그 결과가 오늘의 참가자 전원과 함께 저장된다.

## Blockers

작업 03. 비교할 후보가 있어야 선택을 시작할 수 있다.

## Acceptance criteria

- [x] 두 식당이 한 번에 하나씩 짝지어 제시되고, 하나를 고르면 다음 비교로 넘어간다.
- [x] 고른 쪽이 다음 비교에 그대로 남고, 새 후보가 상대로 등장한다.
- [x] 후보가 8개면 정확히 7번 선택한 뒤 최종 결과가 나온다. 후보가 그보다 적으면 (후보 수 − 1)번 만에 끝난다.
- [x] 시작 시 후보 등장 순서가 무작위로 섞인다.
- [x] 최종 화면에 선택된 식당의 이름·카테고리·거리가 표시된다.
- [x] 결정이 저장되고, 저장된 기록에 최종 식당, 오늘 참가자 전원, 결정 시각이 들어 있다.
- [x] 같은 사용자가 곧바로 다시 시작하면 새 결정으로 처리되고 이전 기록을 덮어쓰지 않는다.

## Constraints

- 시스템이나 다른 참가자가 최종 식당을 대신 고르지 않는다. 마지막 한 번까지 세션 진행자의 선택으로 끝나야 한다.
- 저장하는 참가자는 오늘 실제로 참여한 사람들이다.

## Verification

- 후보 8개로 시작해 7번 선택 후 결과가 하나 남는 것을 확인한다.
- 후보를 2개, 3개로 줄인 상태에서도 각각 1번, 2번 만에 끝나는 것을 확인한다.
- 결정 후 저장된 기록을 조회해 최종 식당·참가자 전원·결정 시각이 모두 들어 있는 것을 확인한다.
- 연속으로 두 번 결정하면 기록이 두 건 남는 것을 확인한다.

## Review checkpoint

None.

## Status

completed

## Execution

- Verification: 실제 후보 8개에서 `ROUND 1 / 7`부터 7회 선택해 최종 식당 화면과 저장 안내를 확인했다. 2·3·8개 후보가 각각 1·2·7회에 끝나는 단위 테스트가 통과했고, 연속 저장 두 건이 서로 다른 ID로 남아 최신순 조회됐다.
- Blocker: 없음.
- Revision: 시작 전에 후보 배열을 다시 섞고 첫 후보를 승자로 둔 뒤, 진행자가 고른 승자와 남은 후보를 순서대로 비교한다. 마지막 선택 시 참가자 전원과 결과 저장이 성공해야 결과 화면으로 이동한다.
