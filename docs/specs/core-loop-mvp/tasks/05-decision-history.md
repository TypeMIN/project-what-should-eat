# 05 — 과거 결정 이력 조회

## Outcome

로그인한 사용자가 자신이 참여했던 과거 식사 결정을 최신순 목록으로 볼 수 있다. 각 항목에는 언제, 누구와, 어디로 정했는지가 나온다.

## Blockers

작업 04. 조회할 저장된 결정이 있어야 한다.

## Acceptance criteria

- [x] 로그인한 사용자가 자신이 참여한 과거 결정 목록을 볼 수 있다.
- [x] 각 항목에 결정 시각, 함께한 참가자들의 표시 이름, 최종 식당 이름이 나온다.
- [x] 목록이 최신순으로 정렬된다.
- [x] 본인이 참가자가 아니었던 결정은 목록에 나오지 않는다.
- [x] 참가자로만 포함되었고 직접 진행하지 않은 결정도 본인 목록에 나온다.
- [x] 아직 결정한 적이 없는 사용자에게는 빈 상태 안내가 표시된다.

## Constraints

- 이력은 조회 전용이다. 수정·삭제는 이번 범위에 없다.

## Verification

- 사용자 A와 B가 함께 한 결정, A와 C가 함께 한 결정을 각각 만든 뒤, B로 로그인해 A·B의 결정만 보이고 A·C의 결정은 보이지 않는 것을 확인한다.
- 결정을 두 건 이상 만든 뒤 최신순 정렬을 확인한다.
- 결정 이력이 없는 새 계정에서 빈 상태가 표시되는 것을 확인한다.
- 배포된 주소에서 새 계정을 만들어 작업 01~05의 전체 루프를 처음부터 끝까지 완주할 수 있는 것을 확인한다.

## Review checkpoint

None. 구현 단계가 전체 변경분에 대한 최종 리뷰를 담당한다.

## Status

completed

## Execution

- Verification: A가 진행하고 A·B가 참여한 결정 3건이 A와 B 모두에게 보였고, B 화면에는 진행하지 않은 결정도 참가자 이력으로 표시됐다. C의 API 이력은 결정이 존재하는 상태에서도 `[]`였으며, 브라우저 목록은 최종 식당·민지/준호·시각을 최신순으로 표시했다.
- Blocker: 없음.
- Revision: 조회는 현재 사용자의 참가자 연결 행에서 결정 ID를 먼저 구한 뒤 해당 결정과 모든 참가자 표시 이름만 조합한다. 수정·삭제 API는 두지 않았다.
