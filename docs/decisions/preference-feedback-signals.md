# 선호 학습을 위한 방문과 평가 신호

## Decisions

- A/B 비교의 승패는 선택을 수행한 세션 진행자의 선호 신호로만 사용하고 다른 참가자의 개인 선호로 확대하지 않는다.
- 최종 식당으로 선택되었다는 사실 자체는 어느 참가자의 선호 신호로도 사용하지 않는다.
- 최종 식당 선택 후 오늘의 참가자 각자는 자신의 기록에서 해당 식당을 `좋다`, `싫다`, `실제로는 방문하지 않음` 중 하나로 표시할 수 있다.
- `좋다`와 `싫다`는 평가한 사용자 본인의 가장 강한 선호 학습 신호로 사용한다.
- `실제로는 방문하지 않음`은 해당 사용자가 그 식당을 방문했다는 추정을 취소하며 선호 신호로 사용하지 않는다.
- 사용자는 추천 세션을 통해 선택하지 않았더라도 실제로 방문한 식당을 별도로 찾아 `좋다` 또는 `싫다` 개인 평가를 남길 수 있다. 이 평가도 세션 후 개인 평가와 같은 직접 선호 신호로 사용한다.

## Boundaries

- 평가하지 않은 참가자를 실제 방문자로 기본 간주할지, 평가 요청과 수정 화면을 어떻게 제공할지는 아직 정하지 않았다.
- 개인 평가의 시간 감쇠, 평가 변경 규칙, A/B 승패 대비 개인 평가의 구체적인 수치 가중치는 아직 정하지 않았다.
- `실제로는 방문하지 않음`은 식당에 대한 부정 평가가 아니며 그룹의 최종 선택 기록을 삭제하지 않는다.

## Why

진행자 한 명의 선택과 그룹의 최종 결정은 다른 참가자의 실제 취향을 보장하지 않는다. 실제 방문 후 각자가 직접 남긴 평가는 선택권이 없었던 참가자의 취향까지 왜곡하지 않으면서 가장 명확한 학습 신호를 제공한다. 추천 밖 방문도 받을 수 있어야 서비스 외부에서 형성된 취향도 개인 모델에 반영할 수 있다.

## Reconsider when

- 사용자가 식후 평가를 거의 남기지 않아 개인 모델 개선에 필요한 직접 신호가 충분히 축적되지 않는 경우.
- 추천 밖 방문 평가에서 허위·중복·잘못된 장소 선택이 데이터 품질을 반복적으로 떨어뜨리는 경우.

## Still-rejected alternatives

- 최종 선택을 참가자 전원의 긍정 신호로 사용 — 선택하지 않은 참가자의 선호를 잘못 학습한다. 최종 선택과 개인 평가가 실제로 강하게 일치한다는 데이터가 확인되면 재검토한다.
- `실제로는 방문하지 않음`을 부정 평가로 사용 — 방문 여부 정정과 음식 선호를 혼동한다.
